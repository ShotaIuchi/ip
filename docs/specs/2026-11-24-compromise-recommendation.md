# 妥協案を推奨にするときの決まり（rules プラグイン）

- 状態: 承認済み
- 作成日: 2026-11-24

## 目的

ベストプラクティスの案が、今の実装や環境のせいで本当に採れないことがある。そのときは妥協案を推奨にしてよいことにする。
ただし、妥協案であることと妥協した理由を必ず明示させ、工数を理由にした妥協と区別できるようにする。

## やること

- `plugins/rules/rules/no-effort-compromise.md` に、妥協案を推奨にしてよい条件を書く
  - 工数以外の具体的な障害があり、ベストプラクティスの案を今は採れないときだけ
  - 障害として認めるもの: 既存の振る舞いや公開している API を壊す、使っているライブラリ・基盤・外部サービスが対応していない、前提になる仕組みが無く今は実現できない、動かすときの費用、運用の手間、依存が増える
  - 「作り直しが大変」「変更が大きい」だけでは認めない
  - 並びと書き方は recommended-first.md を見るよう参照を書く
- `plugins/rules/rules/recommended-first.md` に、妥協案を推奨にするときの並びと書き方を書く
  - 妥協案を一番上に置き、「（推奨：妥協案）」と付ける
  - 妥協した理由を必ず書く。理由には、どの障害か（上の条件のどれか）と、それがなぜベストプラクティスの案を妨げるかを具体的に書く
  - ベストプラクティスの案を必ず2番目に置き、「（ベストプラクティス）」と付け、何が解消すれば採れるかを書く
  - 妥協の条件は no-effort-compromise.md を見るよう参照を書く
  - 今ある決まりのうち、これと食い違うもの（「手軽な案や妥協した案を、一番上（推奨）に置くこと」の禁止など）を、上の条件を満たす「（推奨：妥協案）」は除く形に直す
- rules プラグインのバージョンを 0.3.0 に上げ、`description`（`.claude-plugin` と `.codex-plugin` の両方）と README の rules の行を更新する

## やらないこと

- 他のルールファイル（question-only-response.md、verify-before-concluding.md）の変更
- フック（`hooks/inject.py`、`hooks/hooks.json`）の変更
- 他のプラグインのスキルの文面の変更

## 決めた方針

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 妥協してよい条件 | 工数以外の具体的な障害があるときだけ。「作り直しが大変」は不可 | ユーザーの回答。「工数を理由に妥協しない」と矛盾させないため |
| ベストプラクティス案の扱い | 2番目に必ず置き、「（ベストプラクティス）」と付け、何が解消すれば採れるかを書く | ユーザーの回答。既存の「一番よい案を示さずに、妥協した案だけを示すこと」の禁止と一貫させる |
| 書く場所 | 条件は no-effort-compromise.md、並び・ラベル・理由の書き方は recommended-first.md。互いに参照する | ユーザーの回答。決まりをそれぞれ1か所にする |
| ラベル | 通常は「（推奨）」、妥協のときは「（推奨：妥協案）」 | ユーザーの指定 |
| 選択肢を示さずに妥協案で進めるとき | 選択肢を並べない場面（実装中に自分で決めるときなど）でも、妥協案を採ったなら、妥協案であることと理由を報告に書く | 理由を必ず書くという依頼の趣旨を、質問しない場面にも及ぼすため |
| 聞かずに妥協案で進めてよい障害 | ユーザーの意思では動かせない障害（公開 API を壊す・対応していない・前提の仕組みが作れない）のときだけ。費用・運用の手間・依存は、受け入れるかをユーザーが選べるので、自分で妥協案を採らず選択肢として示して聞く | build の3周目のレビュー指摘に対するユーザーの回答 |
| バージョン | 0.2.0 → 0.3.0 | ルールの追加・変更で、前回も 0.1.0 → 0.2.0 にしたため |
| 作業場所 | main から作った worktree `../ip-rules-compromise`（ブランチ `rules/compromise-recommendation`） | 前回のルール追加と同じやり方。main に recommended-first.md があり、今のブランチ dev/peer-ai には無いため |

## 受け入れ条件

- AC-1: no-effort-compromise.md に、妥協案を推奨にしてよい条件（工数以外の具体的な障害のときだけ、認める障害の一覧、「作り直しが大変」だけでは不可）が書かれている
- AC-2: recommended-first.md に、妥協案を一番上に置き「（推奨：妥協案）」と付けることが書かれている
- AC-3: recommended-first.md に、妥協した理由を必ず書くこと、理由にはどの障害かと、なぜベストプラクティスの案を妨げるかを書くことが書かれている
- AC-4: recommended-first.md に、ベストプラクティスの案を2番目に置き「（ベストプラクティス）」と付け、何が解消すれば採れるかを書くことが書かれている
- AC-5: 2つのファイルが互いを参照し、同じ決まりを両方に重ねて書いていない
- AC-6: 2つのファイルの中で、条件を満たした「（推奨：妥協案）」を禁じているように読める文が残っていない
- AC-7: 選択肢を示さずに妥協案で進めたときも、妥協案であることと理由を報告に書くことが、どちらかのファイルに書かれている
- AC-8: rules のバージョンが `.claude-plugin/plugin.json` と `.codex-plugin/plugin.json` の両方で 0.3.0 になり、`description` と README の rules の行（バージョンと説明）が更新されている
