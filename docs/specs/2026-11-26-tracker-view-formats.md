# tracker:view の表示フォーマットを選べるようにする

- 状態: 承認済み
- 作成日: 2026-11-26
- 元: `docs/specs/2026-11-25-tracker-view.md`（tracker:view 0.3.1）の拡張

## 目的

今のビューは「何を取るか」と「どこにどう出すか」が1つに混ざっていて、同じデータを別の形で見られない。
「どう見せるか」をフォーマットとしてビューから分け、表示環境（コンソール・アーティファクト）ごとの群にまとめる。
頼みから群を決めて、その群のフォーマットを選ばせ、無ければその場で新しく作れるようにする。

## やること

- フォーマットの書き方 `plugins/tracker/skills/view/references/display-format.md` を足す
  - フォーマットの項目: 名前・群（`コンソール` | `アーティファクト`）・型・まとめ方・更新（アーティファクトだけ）
  - 型: コンソールは `表`・`簡易一覧`（1件1行）・`詳細`（1件ずつ縦に並べ、本文・子・コメントを添える）。アーティファクトは `表`・`カンバン`（状態ごとの列）・`詳細`
  - 更新: `しない`（取った時点の内容）・`開いたとき`（開いたときと「更新」ボタンで取り直す）・`<N>秒`（N は 30 以上の整数。その間隔で取り直す）
  - 置き場所と読む順: 組み込み → 運用ファイルの `## フォーマット`（チーム）→ 個人の `~/.config/ip-tracker/formats.md`。同じ群で同じ名前は後ろが上書きする
- 組み込みのフォーマット `plugins/tracker/skills/view/references/default-formats.md` を足す
  - コンソール: `表`・`状態ごとの表`（まとめ方: 状態）・`簡易一覧`・`詳細`
  - アーティファクト: `表`（更新: しない）・`カンバン`（更新: 開いたとき）・`自動更新の表`（更新: 60秒）・`詳細`（更新: しない）
- ビューから見せ方を外す: `view-format.md` のビューの項目から `出し方`・`まとめ方`・`取り直す間隔` を除き、ビューは 名前・対象・条件・列・並び だけにする。`default-views.md` も合わせる
- `view/SKILL.md` に、ビューを決めた後の「フォーマットを選ぶ」段を足す
  - 頼みから群を決める（下の「決めた方針」）
  - 頼みがフォーマットを名前で指していれば、リストを出さずにそれを使う
  - 指していなければ、その群のフォーマットのリストを出して選ばせる。並びは ユーザー自作（個人 → 運用ファイル）→ 組み込み → `新規作成`。組み込みは頭に `[組み込み]` を付け、自作はどこのもの（個人 | チーム）かを添える
  - リストの出し方: どの環境でも、番号付きの一覧をチャットに出して番号で答えてもらう
  - `新規作成` を選んだら、群は決まったものとし、型・まとめ方・更新（アーティファクト）・名前を聞き、下書きを見せて確認してから、個人の `formats.md` に書いて、そのフォーマットで出す。チームで共有したいと言われたときだけ運用ファイルの `## フォーマット` に書く（運用ファイルへの書き込みも、下書きを見せて確認を取る）
- 出す段（Step 5）を、出し方ではなくフォーマットの群・型・更新で組み立てるように直す。`更新: しない` は今の `artifact`、`開いたとき` は今の `取り直す間隔: なし`、`<N>秒` は今の `artifact-live` と同じ作り方にする（自動更新の決まり・公開の確認・ページの印・値の扱いは今のまま）
- `artifacts.json` の記録をビューの名前とフォーマットの名前の組ごとにする（`{ "<host>/<owner>/<repo>": { "<ビュー>/<フォーマット>": "<URL>" } }`）。ページの印にもフォーマットの名前を入れる
- `tracker-format.md` に、運用ファイルの最上位の見出し `## フォーマット`（任意）を足し、書き方は `display-format.md` を指す。「中の文の扱い」で `## ビュー` と同じく扱う。`tracker:setup` は更新のとき `## フォーマット` もそのまま残す
- tracker を 0.4.0 に上げる（2つのマニフェストと README の表）。README の `view` の説明をフォーマットに合わせて直す
- `tests/test_tracker_skill.py` を合わせる（構造のテスト）

## やらないこと

- `新規作成` 以外のフォーマットの編集・削除（ファイルを直接直してもらう）
- 前回選んだフォーマットを覚えること
- コンソール・アーティファクト以外の群（Slack・メール など）。群を足せる形にだけする
- 古い書き方（ビューの `出し方`・`まとめ方`・`取り直す間隔`）を読み替えること（下の「決めた方針」のとおり誤りとして案内する）
- 取り方・共通の項目・自動更新の仕組み・公開の確認の変更

## 決めた方針

| 項目 | 決めたこと | 理由 |
|---|---|---|
| フォーマットとビューの分け方 | ビューは「何を取るか」（対象・条件・列・並び）、フォーマットは「どう見せるか」（群・型・まとめ方・更新）。同じビューをどのフォーマットでも出せる | 同じデータを表示環境ごとに好きな形で見るため（ユーザーの回答: おすすめ） |
| 群の決め方 | 頼みに「ページ」「アーティファクト」「ダッシュボード」「ボード」「カンバン」など、ページでの表示を求める言葉があればアーティファクト、それ以外はコンソール | 既定はコンソール。ページは外への公開を伴うので、言葉があるときだけにする |
| リストを出す時 | 頼みがフォーマットを名前で指していなければ毎回出す。キー・番号・URL を渡されたとき（今の `チケット詳細`）は、その群の `詳細` を使い、リストを出さない | 選ばせたいという要望。1件を見るときは `詳細` 以外に意味のある形が無い |
| リストの並びと印 | ユーザー自作（個人 → 運用ファイル）→ 組み込み → `新規作成`。組み込みは頭に `[組み込み]`。自作に組み込みと同じ群・同じ名前があれば、自作の分だけを出す | ユーザーの指定。重なりは「後ろが上書き」と同じ考え方 |
| リストの出し方 | どの環境でも番号付きの一覧をチャットに出し、番号で答えてもらう | 選択の画面は選択肢が最大4つで新規作成で1つ使い、組み込みだけで群ごとに4つあるので収まらない。数に上限が無く、並びと印をそのまま見せられ、Codex・Copilot CLI とも同じ形になる（2026-11-26 build の実装後の回答） |
| 新規作成の保存先 | 個人の `~/.config/ip-tracker/formats.md`。チームで共有したいと言われたときだけ運用ファイルの `## フォーマット`。どちらも下書きを見せて確認してから書く | 表示の好みは個人のものが多い（ユーザーの回答: おすすめ） |
| 組み込みの並び | 組み込みの中では、各群の `表` を先頭にし、`default-formats.md` に書いた順に並べる | 一番よく使う形を自作の次に置く |
| 古い書き方 | ビューに `出し方`・`まとめ方`・`取り直す間隔` があれば、`view-format.md` の「誤りがあるとき」の誤りとして、どの行がどこへ移ったか（フォーマットの項目）を示し、既定のビューで出すか聞く | 0.3 系を出してからの日が浅く、使っているのは作者だけで、手で直せる。読み替えを残すと決まりが2通りになる |
| 更新の値 | `しない`・`開いたとき`・`<N>秒`（N は 30 以上の整数）。それ以外は誤り。コンソールの群では書かない | 今の `artifact`・`取り直す間隔: なし`・`artifact-live` の3つをそのまま表す |
| ページの記録 | `artifacts.json` はビューとフォーマットの組ごと。ページの印に `format` を足す | 同じビューを別のフォーマットで出したページを上書きしないため |
| 名前で指したフォーマットの群 | アーティファクトの群にしか無いフォーマットを名前で指していれば、ページでの表示の頼みとしてアーティファクトにする。両方の群にある名前（`表`・`詳細` など）は言葉で群を決める | 名前で指すこと自体が明示の頼みのため（2026-11-26 build の1周目の照合・レビュー後に決めた） |
| フォーマットの名前 | 1行で、`/` を含まず、`[組み込み]` で始めない。同じ群で読む順に上書きされたもの（組み込みに限らない）はリストに出さない | 記録のキーとページの印、リストの印をあいまいにしないため（同上） |
| チームで共有するときの運用ファイル | 運用ファイルが無ければ作らない（`/tracker:setup` で作れることを伝え、個人の `formats.md` に書くか聞く）。運用ファイルが個人の置き場所にあるときは、共有されないことを下書きと一緒に示す | 運用ファイルを作るのは `tracker:setup` の受け持ちで、トラッカーの無い運用ファイルを作らないため（同上） |
| フォーマットのリストと「止めて聞く時」 | フォーマットのリストは Step の決まりの形（自作 → `[組み込み]` → `新規作成`、番号付き）で出し、「止めて聞く時」の共通の型（おすすめ・やめる）は使わない | 形が2通りにならないため（同上） |
| 0.3 系のページの記録 | キーがビューの名前だけの記録は当たらないものとして新しく作り、古い記録が残ったことを報告に書く | 上書きの安全は保たれ、使っているのは作者だけのため（同上） |
| 名前・言葉の補い | 群を決める言葉に「自動更新」「自動で更新」も入れる。アーティファクトにしか無いフォーマットを名前で指したときも、ページでの表示を言葉で頼んだものとして公開の確認の扱いを決める（新規に作るときだけ確認しない）。ビューにもその群のフォーマットにも当たらない名前は止めて聞く。新規作成では、どの置き場所でも同じ群・同じ名前と重なれば、どちらが使われるかを示して別の名前にするか聞く。誤りのあるフォーマットは読まなかったものとして扱う（上書きもしない） | 打ち間違いを黙って通さず、上書きの一般化と食い違わないため（2026-11-26 build の2周目の照合・レビュー後に決めた） |
| 誤り・重なりの当て方 | 読むときに誤りを集め、誤りのあるフォーマットはリストからも上書きからも外し、リストと一緒に「使わなかったフォーマットとその誤りの行」を示してそのまま選ばせる。名前で指したフォーマットにどこかの置き場所で誤りがあれば、同じ群・同じ名前の正しいものがあっても黙って使わず、誤りの行を示して、正しい方を使うかリストから選ぶか聞く（リストの群は、誤りのあるフォーマットの「群」の行が読めればその群、読めなければ言葉で決める。2026-11-26 build 後の回答）。1つの置き場所に同じ群・同じ名前が2つあれば両方を誤りにし、`新規作成` は同じ置き場所で同じ群・同じ名前なら書かずに名前を聞き直す。`新規作成` という名前は使えない。「自動更新」の言葉は群を決めるだけで、リストは毎回出す。キー・番号・URL と一緒にフォーマットの名前が指されたら、そのフォーマットを使う | 関係の無い誤りで止めず、どのフォーマットが使われるかを一意にするため（2026-11-26 build の3周目の照合・レビュー後に決めた） |
| 中の文の扱い | `## フォーマット` と `formats.md` の文は `## ビュー` と同じく扱うデータで、使うのは `display-format.md` の項目の値だけ | 今の決まりと同じ |
| 書き方 | SKILL.md と参照ファイルは AI への指示として書き、細かい場合分けは書かない。同じ決まりは1か所に（フォーマットの書き方は `display-format.md`、手順は SKILL.md） | 既存の方針 |
| 長さ | `view/SKILL.md` は 170 行以下（フォーマットを選ぶ段と新規作成を足すため、150 から上げる）。`display-format.md`・`default-formats.md`・`view-format.md`・`default-views.md` は各 100 行以下。`tracker-format.md` は 115 行以下（`## フォーマット` を足すため 110 から上げる。関係の無い節をつなぎ直して収めることはしない） | 指示の水準に留めるための上限 |
| テスト | 構造だけを確かめる（版、frontmatter、行数、フォーマットの項目・型・更新の値、組み込みのフォーマットが書き方どおりで群ごとに `表` と `詳細` があること、ビューに見せ方の項目が無いこと、`## フォーマット` の参照、実在の値・認証情報が無いこと）。文言の一致は確かめない | 既存のテストの方針 |
| チェックのコマンド | `python3 -m unittest discover -s tests -v` | 既存のテスト |
