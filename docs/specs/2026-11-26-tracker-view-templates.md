# tracker:view のアーティファクト用フォーマットに HTML テンプレートを持たせる

- 状態: 承認済み
- 作成日: 2026-11-26
- 元: `docs/specs/2026-11-26-tracker-view-formats.md`（tracker 0.4.0）の拡張

## 目的

アーティファクト用のフォーマットは型の名前だけで、ページの HTML・見た目・ボタン・安全の決まりを毎回 AI が書いている。
そのため見た目が毎回ぶれ、安全の決まりが書き直しのたびに抜ける危険があり（0.4.0 の build で `\u003c` の決まりが一度消えた）、出すのも遅い。
見た目は実物のテンプレートに、動く部分と安全の決まりはプラグインの1つのスクリプトにまとめ、AI はデータを差し込むだけにする。

## やること

- 共通の動く部分 `plugins/tracker/skills/view/templates/runtime.js` と描画の `templates/render.js` を足す（分け方は「決めた方針」の「動く部分の分け方」）。2つでページの中の次を受け持つ
  - 印の JSON（`<script type="application/json" id="ip-tracker-view">`）を読み、テンプレートの `data-ipt` の印に値を入れる
  - 値はすべて文字として出す（`textContent`）。リンクにするのは `https://` で始まる URL だけ
  - 更新が `開いたとき`・`<N>秒` のトラッカーを `mcp` 機能の `watchTool` で取り直す（`<N>秒` は N × 1000 を `refetchInterval` に、`開いたとき` は付けない）。「更新」ボタンで `invalidate` する。続きのページを取り、切れたらそのことと件数を出す
  - 取り直した結果に、印の JSON にある決まり（共通の項目の当て方・状態と種類の対応・状態の順・取った後の絞り込み・並び・まとめ方・列）を当てる
  - 最終取得の時刻（結果に `cache` があれば `storedAt`、無ければ受け取った時刻）、取れなかったトラッカーと理由、取った時点の内容の分（誰がいつ取ったか、`@自分` なら作った人の担当）、自動で取り直す分の `@自分` の注記を出す
  - `claude.use("mcp")` が `null`・接続が無い・断られたときは、自動で取り直すトラッカーの分に理由だけを出す
- 見た目のテンプレートを型ごとに足す: `templates/table.html`（表）・`templates/kanban.html`（状態ごとの列にカード）・`templates/detail.html`（1件ずつ、項目の後に本文・子・コメント）
  - 置く印（`data-ipt`）: タイトル・件数・最終取得の時刻・「更新」ボタン・取れなかったもの・取った時点の内容の注記・本体（表の行、カンバンの列とカード、詳細の項目）。型ごとに要る印を `display-format.md` に書く
  - ライト・ダークの両方の配色、幅が狭くても読めるレイアウト（Artifact の `artifact-design` スキルの決まりに従う）
  - `<script>` は、印の JSON の入れ物と `render.js`・`runtime.js` の読み込みだけ
- `display-format.md` に、アーティファクトのフォーマットの項目 `テンプレート` を足す。組み込みは `templates/<型>.html`。自作は `~/.config/ip-tracker/templates/<ファイル名>.html` だけを指せる。書き方（型ごとに要る `data-ipt` の印、`<script>` を置かないこと）と、誤りの扱いもここに書く
- `default-formats.md` のアーティファクトの4つに `テンプレート` を書く。コンソールの4つに、出力の見本（Markdown）を添える
- `view/SKILL.md` の出す段を、テンプレートを使う形に直す
  - テンプレートを写し、印の JSON だけを書く（データ・決まり・取り直す入力・ページの印の `repo`・`view`・`format`）。JSON の中の `<` は `\u003c` に直す
  - ページは、写したテンプレートを本体に、`render.js`・`runtime.js` を一緒のファイルとして公開する。`mcp` の宣言は今までどおり使うツールだけ
  - ページの中の動く決まり（値の出し方・自動更新の組み方など）は SKILL.md から消し、`runtime.js` に任せることを書く
  - 公開の確認・ページの印による上書きの確かめ・`artifacts.json`・非公開での作成は今のまま
- `新規作成` でアーティファクトのフォーマットを作るとき、見た目を変えたいと言われたら、組み込みのテンプレートを `~/.config/ip-tracker/templates/` に写して直し、そのファイルを `テンプレート` に書く（下書きを見せて確認してから書く）
- tracker を 0.5.0 に上げる（2つのマニフェストと README の表）。README の `view` の説明にテンプレートを足す
- `tests/test_tracker_skill.py` に構造のテストを足す

## やらないこと

- Artifact の既成の型（「Data」など）を土台にすること
- 自作のテンプレートに `<script>` を許すこと、運用ファイル（`TRACKER.md`）の `## フォーマット` からテンプレートを指すこと
- JS を実際に動かすテスト（Node.js などの新しい依存を足すこと）
- コンソール用の見た目をテンプレートのファイルにすること（見本を添えるだけ）
- 取り方・共通の項目・フォーマットの選び方・公開の確認の決まりの変更

## 決めた方針

| 項目 | 決めたこと | 理由 |
|---|---|---|
| ページの土台 | プラグインに自前のテンプレートを持つ。Artifact の「Data」型は使わない | 「Data」型には一定の間隔で取り直す仕組みが無く `<N>秒` ができない。書き方が Artifact のデータの保存場所への文書に変わり、今の公開の確認・印・`artifacts.json` を作り直すことになる。GitHub の分はアップロードしたファイルになり、見る人の権限に関係なく全員が読める（ユーザーの回答: おすすめ） |
| 分け方 | 動く部分と安全の決まりは `runtime.js` の1か所、見た目は型ごとの HTML と CSS | 安全の決まりを写しにせず、テンプレートを足しても抜けないようにするため（ユーザーの回答: おすすめ） |
| 自作のテンプレート | HTML と CSS だけ。印の JSON の入れ物と `render.js`・`runtime.js` の読み込み以外の `<script>`、`on…=` の属性、外のファイルの読み込みがあれば誤り。置き場所は `~/.config/ip-tracker/templates/` だけ | 自作の見た目で安全の決まりが崩れないため。運用ファイルは PR で誰でも書き換えられるので指せない（ユーザーの回答: おすすめ） |
| データの差し込み | AI はテンプレートを写して、印の JSON の中身だけを書く。ほかの部分は変えない | 見た目を毎回そろえ、書き出す量を減らすため |
| 印の JSON の形 | `repo`・`view`・`format`・`title`・取った時刻・トラッカーごとの `rows`（取った時点の内容）または取り直す入力（`## ライブ` の決まりで組む）・決まり（当て方・対応・順・絞り込み・並び・まとめ方・列）・取れなかったもの。形は `display-format.md` に書く | `runtime.js` とテンプレートと SKILL.md が同じ形を使うため。今の印（`repo`・`view`・`format`）を広げる |
| テンプレートの誤り | 型に要る `data-ipt` の印が無い、許していない `<script>` や `on…=` がある、置き場所の外を指す、ファイルが無いときは、そのフォーマットを誤りとして `display-format.md` の「誤りがあるとき」のとおりに扱う | 今の誤りの扱いにそろえる |
| 見た目 | 組み込みはライト・ダークの両方、幅が狭くても読める。タイトルと件数を上、最終取得の時刻と「更新」ボタンを右上（`しない` では「更新」ボタンを出さない）、取れなかったものと注記は本体の上 | ユーザーの要望（どこにタイトル・ボタンを出すか） |
| コンソール用 | 各フォーマットに出力の見本（Markdown）を添える | コンソールは Markdown なので見本で足りる |
| テスト | 構造だけを確かめる: `runtime.js`・`render.js` が値を `innerHTML`・`outerHTML`・`insertAdjacentHTML`・`document.write` に入れていない、`textContent`・`watchTool`・`invalidate`・`refetchInterval` を使う、`https://` の確かめがある。テンプレートに型ごとに要る `data-ipt` の印がそろう、許していない `<script>`・`on…=` が無い。組み込みのフォーマットの `テンプレート` が実在する。版・行数・実在の値・認証情報 | JS を動かすには新しい依存が要るため |
| 長さ | 動く部分は `templates/runtime.js`（取り直しと状態）と `templates/render.js`（描画）の2つに分け、`runtime.js` は 700 行以下・`render.js` は 450 行以下、1行1文で詰めない（build 3周目の後、600 行に詰めたことで読みやすさが損なわれたため分けた。ユーザーの回答: おすすめ。分けた後、取り直しと状態の変化は互いに呼び合う1つのまとまりで、さらに分けるとファイルどうしが互いを呼ぶ形になるため、`runtime.js` だけ 650 行に上げた。ユーザーの回答: おすすめ。build 4周目の後、上限に当たるたびに上げる繰り返しを止めるため、今の大きさに余裕を持たせた 700・450 に一度で決め直した。ユーザーの回答: 推奨）、各テンプレートは 150 行以下、`view/SKILL.md` は 170 行以下のまま、`display-format.md` は 120 行以下（`テンプレート` の書き方を足すため 100 から上げる） | 指示とコードを読める大きさに留めるため |
| 承認が要るコネクタ | watch が `approval_required` を返したら、そのトラッカーの所に「承認して取る」ボタンを出し、押されたら `callTool` で1回取って出す。watch は解除しない | mcp の決まり（watch は承認を求めない。ボタンからの `callTool` で承認を求める）。build 1周目の後に決めた（ユーザーの回答: おすすめ） |
| 誤りのときの内容 | 許可の拒否（`needs_reauth`・`server_not_connected`・`blocked_by_policy`・`consent_required`・`not_in_manifest` など）は前の内容を引っ込めて理由を出す。それ以外（知らない code を含む）は前の内容を残して理由を添える。`user_changed` はページ全体で何も出さず、以降は呼ばない | mcp の決まり（build 1周目の後に決めた） |
| 続きのページと1件ずつの呼び出し | 続きのページは上限を置かず全部を取る（前の版の「全部を取る」）。型が `詳細` の1件ずつの呼び出しは同時に4件まで。取り直しの途中で新しい結果が来たときの扱いは「取り直しの重なり」の行に従う | 前の版の決まりにそろえ、呼び出しが一度に集中しないため（build 1周目の後に決めた。ユーザーの回答: おすすめ） |
| 最終取得の時刻 | 右上には、トラッカーごとの時刻のうち一番古いものを1つ出す。トラッカーごとの時刻は注記に出す | ページのどこもその時点より新しいと言えるため（build 1周目の後に決めた。ユーザーの回答: おすすめ） |
| ページのタイトル | テンプレートに `<title>` を置かない。公開するときの `title` と、`render.js` が付ける `document.title` で表す（分け方の行に合わせて描画の側に置く。build の最後の確認で直した） | 写すときに書き換えるのを印の JSON だけにするため（build 1周目の後に決めた。ユーザーの回答: おすすめ） |
| 承認が要る呼び出し（2周目の後、3周目の後に直した） | watch の `approval_required` は mcp の決まりどおり、そのトラッカーの内容を引っ込めて「承認して取る」ボタンを出し、watch とボタンは残す（承認して取った内容は、次に watch が `approval_required` を返すまで出る）。一度 `approval_required` になったトラッカーは、承認して取れた後も、自動の取り直しでは続きのページと1件ずつを呼ばない（それらはボタンからだけ呼ぶ。1ページ目だけで済む watch の結果は出す）。この印は許可の拒否か見る人が変わったときに消す。ボタンは、そのトラッカーの要る呼び出し（一覧・続きのページ・1件ずつ）をまとめて行う | mcp の決まり（mcp.d.ts: watch の承認の誤りは内容を引っ込める。承認は callTool が待つ間に求められ、呼び出しごとに要るコネクタもある）。見る人に操作なしで承認を何度も求めないため。2周目の後にまとめ役が「引っ込めない」と決めたのは mcp の決まりに反していたので、3周目の後に直した（ユーザーの回答: おすすめ） |
| 誤りの扱いの経路（2周目の後） | 誤りの code の分け方（`user_changed` は止める、許可の拒否は引っ込める、ほかは残す）は、watch・続きのページ・1件ずつ・承認のどの経路の誤りにも同じに当てる。続きのページや1件ずつで許可の拒否が返ったら、そのトラッカーの内容をまるごと引っ込める | 経路によって安全の決まりが変わらないため。build 2周目の後にまとめ役が決めた |
| 取り直しの重なり（2周目の後） | 取り直しの途中で新しい結果が来ても、今の取り直しは止めずに終え、その後で一番新しい結果だけを取る（見る人の「更新」だけは今の取り直しを止める）。1ページ目の行はすぐ出し、1件ずつの結果は届いた分から入れる。1件ずつの結果はキーと更新日で手元に残し、変わっていない行は呼び直さない | 間隔より取り直しが長いとページが一度も仕上がらないため。build 2周目の後にまとめ役が決めた |
| 自作テンプレートを確かめる時 | 読むとき（Step 3）に確かめて誤りのあるフォーマットを外す。写すとき（Step 6）にもう一度確かめ、そこで誤りが見つかれば（その間にファイルが変わったなど）出さずに誤りの行を示して止まる | 「誤りがあるとき」の扱いにそろえるため。build 2周目の後にまとめ役が決めた |
| 動く部分の分け方（3周目の後） | `render.js` は印の JSON とテンプレートの印から描画だけを受け持ち、`runtime.js` は取り直し・誤りの扱い・状態を受け持つ。トラッカーの状態は1つの名前付きの状態（取っていない・取得中・承認待ち・承認して取っている・拒否された・止めた など）で表す。テンプレートは2つを読み込み、ページは2つを一緒のファイルとして公開する。自作のテンプレートで許す `<script>` も、印の JSON の入れ物とこの2つの読み込みだけ | 読める大きさに留めつつ責務を分けるため（ユーザーの回答: おすすめ） |
| 取れなかったときの表示（3周目の後） | 行が無く、取れなかったトラッカーがあるときは、本体に「取れなかった（理由は上）」を出し、件数は出さない。「該当するチケットは無い」はどのトラッカーも取れたうえで0件のときだけ | 0件と取れなかったを取り違えないため（build 3周目の後に決めた） |
| 再生と更新（3周目の後） | `cache.revalidating` の再生は、続きのページや1件ずつが要るときも1ページ目の行を仕上がっていない内容として出し（切れたことと件数を示す）、続きは新しい結果で取る。`詳細` では、手元に残した1件ずつの結果を行を作るときに当て、取り直しの途中で本文が消えないようにする。`invalidate` が断られたら、最後に受け取った結果から取り直す | mcp の決まり（一時的な誤りでは最後の内容を出したままにする）と、表示が欠けないため（build 3周目の後に決めた） |
| チェックのコマンド | `python3 -m unittest discover -s tests -v` | 既存のテスト |
