# 選択肢は推奨を一番上に置く

ユーザーに選択肢を示すとき（質問のツールで聞くときも、文章で案を並べるときも）は、推奨する案を一番上に置く。

## 推奨の決め方

- 推奨は、工数を度外視したベストプラクティスの案にする（「工数を理由に妥協しない」の基準と同じ）
- 比べる基準は、正しさ・安全・保守性・既存の設計との一貫性にする
- 「今の実装を変えずに済む」「既存のルールや作りに手を入れずに済む」ことを、推奨の理由にしない。既存を直すのが一番よいなら、それを推奨にする
- ただし、工数以外の具体的な障害でベストプラクティスの案を今は採れないときは、妥協案を推奨にしてよい。その条件と、選択肢を並べずに妥協案で進めたときの報告の決まりは、「工数を理由に妥協しない」の「妥協案を推奨にしてよい条件」（no-effort-compromise.md）に従う

## 必須

- 推奨の案には「（推奨）」と付け、なぜ推奨なのかを一言添える（妥協案を推奨にするときは、下の「妥協案を推奨にするときの書き方」に従う）
- 推奨は1つだけにする

## 禁止

- 推奨を決めずに、案を並べるだけにすること（好みの問題で優劣が本当に無いときは、推奨を付けず、そう書く）
- 手軽な案や妥協した案を、一番上（推奨）に置くこと（条件を満たした「（推奨：妥協案）」は除く）
- 推奨を2番目以降に置くこと（並びの都合や、案を出した順番に合わせるなど）
- 妥協案を推奨にするのに、「（推奨）」とだけ付けて、妥協案であることを書かないこと

## 妥協案を推奨にするときの書き方

- 妥協案を一番上に置き、「（推奨：妥協案）」と付ける
- 妥協した理由を必ず書く。理由には、どの障害か（「工数を理由に妥協しない」の「妥協案を推奨にしてよい条件」にある「障害として認めるもの」のどれか。no-effort-compromise.md）と、それがなぜベストプラクティスの案を妨げるかを具体的に書く
- ベストプラクティスの案を必ず2番目に置き、「（ベストプラクティス）」と付け、何が解消すれば採れるかを書く

例:

- A（推奨：妥協案）— B は戻り値の形を変え、外部の利用者が使う公開 API を壊すため
- B（ベストプラクティス）— 外部の利用者が新しい戻り値の形に移り終えれば採れる
