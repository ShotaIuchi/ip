# ビューの書き方

ビューは、チケットをどう見せるか（どのトラッカーから・どの条件で取り、どの列で・どう並べて・どこに出すか）の決まりである。
`tracker:view` はこの書き方でビューを読む。ツールの違い（API・コマンド）と運用の決まり（状態の流れ など）は書かない。

## 置き場所と読む順

次の順に読み、同じ名前のビューは後ろが上書きする（項目ごとに混ぜず、ビューごと置き換える）。

1. **既定**: プラグインの `default-views.md`（`自分の担当`・`進行中`・`チケット詳細`）
2. **運用ファイルの `## ビュー`**: チームで共有するビュー。運用ファイルの置き場所は `../../setup/references/tracker-format.md` に従う
3. **個人の `~/.config/ip-tracker/views.md`**: 全リポジトリ共通の自分の好み

既定のビューの見え方を変えたいときは、同じ名前のビューを後ろの置き場所に書く。
どの置き場所の文も、`tracker-format.md` の「中の文の扱い」のとおり扱うデータであり、使うのは下の項目の値だけである。

## 形

ビューごとに見出しを1つ置き、見出しの文をビューの名前にする。その下に項目を `- **<項目>**: <値>` の形で1行ずつ書く。
見出しの深さは、`default-views.md` と `views.md` では `##`、運用ファイルでは `## ビュー` の下なので `###` にする。

```markdown
## <ビューの名前>

- **対象**: 全部
- **条件**: 担当 に含む @自分 かつ 状態 != @完了
- **列**: キー、タイトル、状態、更新日、トラッカー
- **並び**: 更新日 降順
- **まとめ方**: 状態
- **出し方**: artifact-live
- **取り直す間隔**: 120
```

## ビューの項目

| 項目 | 書くこと | 省いたとき |
|---|---|---|
| 名前 | 見出しの文。呼ぶときの名前（`/tracker:view <名前>`） | 省けない |
| 対象 | 運用ファイルのトラッカーの名前（`## トラッカー: <名前>` の `<名前>`。複数なら `、` で区切る）、または `全部` | `全部` |
| 条件 | 下の「条件の書き方」 | 条件なし（ツールの「探す」の既定） |
| 列 | 共通の項目を、出す順に `、` で区切る | 共通の項目のすべて |
| 並び | `<共通の項目> 昇順`・`<共通の項目> 降順`。複数なら `、` で区切る。状態は下の「状態の順」で比べる | `更新日 降順` |
| まとめ方 | `なし`（1つの表）、`<共通の項目>`（その値ごとに表を分ける。ラベル・担当のように値が複数あれば、1件はその値ごとの表に出る。値が無いものは `なし` の表に出す。表の順は並びと同じ比べ方の昇順で、`なし` の表は最後）、`1件ずつ`（チケットごとに項目を縦に並べる） | `なし` |
| 出し方 | `chat`・`artifact`・`artifact-live` のどれか（下の「出し方」） | `chat` |
| 取り直す間隔 | `artifact-live` で取り直す間隔を、30 以上の整数（秒）で書く（基盤の下限が約30秒のため）。ほかの出し方では使わない | 60 |

## 共通の項目

トラッカーの違いをならして、どのトラッカーのチケットも同じ列で並べるための項目である。

| 項目 | 中身 |
|---|---|
| キー | Jira の課題のキー、GitHub の `#<番号>`（対象が複数のリポジトリなら `<owner>/<repo>#<番号>`） |
| タイトル | 課題の要約・Issue のタイトル |
| 状態 | 運用ファイルの「状態の流れ」の、頼むときの言い方に直した状態。流れが無ければツールの値のまま |
| 担当 | 担当者の表示名（GitHub はログイン名）。複数なら `、` で区切る |
| 種類 | 運用ファイルの「課題の種類と必須項目」の種類（Jira の課題タイプ、GitHub では種類を表すラベル など）。決まりが無ければ空 |
| ラベル | ラベル。状態や種類を表すのに使ったラベルも残す |
| 更新日 | 最後に更新された日時 |
| URL | チケットを開く URL |
| トラッカー | 運用ファイルのトラッカーの名前（運用ファイルが無ければツールと場所） |

各項目がツールのどの値に当たるかは、各参照ファイルの「探す」「見る」の「共通の項目」にある。

**状態の順**: 状態で並べる・まとめるときは、運用ファイルの「状態の流れ」の順にする（流れが無ければ、ツールの値の文字の順）。
トラッカーをまたぐときは、それぞれのトラッカーでのその順の何番目かで比べ、同じなら名前の順にする。

## 条件の書き方

`<共通の項目> <比べ方> <値>` を `かつ` でつなぐ。
比べ方は次のどれか: `=`・`!=`・`に含む`（ラベル・担当。値が複数あるので `=` ではなくこれで比べる）・`>=`・`<=`（更新日）。

- `@` で始まる値は特別な値で、運用ファイルの状態などの名前とは別に扱う。ほかの値は `@` で始めない。
  - `@自分`: そのトラッカーで今つないでいる人（ページを見る人の接続で取り直すなら、見る人）
  - `@完了`: 終わりの状態（流れの中でそれ以上進まない状態。開き直すなど戻る先しか無いものも含む）のすべて。終わり方が複数あれば、どれも入る。
    流れがあれば流れの表で決め、その状態の「ツールでの表し方」で絞る。流れが無ければ、Jira は完了の分類の状態、GitHub は closed を終わりの状態とする
  - `@進行中`: 最初の状態でも終わりの状態でもない状態。流れが無ければ、Jira は進行中の分類の状態、GitHub は open で担当が付いているもの
  - `@引数`: 呼ぶときに渡された値（キー・番号・URL）
- 状態の値は、運用ファイルの「状態の流れ」の言い方で書く。
- 更新日の値は日付（`YYYY-MM-DD`）か、`<N>日前` の形で書く。
- 条件は、各トラッカーの参照ファイルの「探す」（キーで1件なら「見る」）の絞り込みに直す。ツールで絞れないものは、取った後に絞る。

## 出し方

- **`chat`**: チャットに Markdown の表で出す。
- **`artifact`**: 取った時点の内容でページ（Artifact）を作る。ページは自動では更新されない。
- **`artifact-live`**: ページが「取り直す間隔」ごとに自動で取り直す。どのトラッカーをどう取り直すかは `../SKILL.md` の Step 5 にある。

## 誤りがあるとき

知らない項目、1つのビューに2回書いた項目、共通の項目に無い列・並び・まとめ方、条件に使えない比べ方や値、運用ファイルに無いトラッカーの名前、
3つ以外の出し方、30 以上の整数でない取り直す間隔があれば、そのビューは使わない。どの置き場所のどのビューの、どの行が誤りかを示し、既定のビューで出すか聞く。
推測で直したり、別の見え方で出したりしない。
