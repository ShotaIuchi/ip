# view: チケットを共通の形で見る

チケットを、トラッカーをまたいで共通の項目にそろえ、ビュー（何を取るか）とフォーマット（どう見せるか）の決まりどおりに出す。読むだけで、チケットには書き込まない。
この文書は流れの目的と決まりを書いたものである。取り方は参照ファイルを見て、ビュー・フォーマットと状況に合わせて自分で組み立てる。

- **ビューの書き方**（項目・共通の項目・条件・置き場所と読む順）: `references/view-format.md`。最初にそれを読む
- **フォーマットの書き方**（群・型・まとめ方・更新・置き場所と読む順）: `references/display-format.md`。最初にそれを読む
- **既定のビュー・組み込みのフォーマット**: `references/default-views.md`・`references/default-formats.md`
- **ツールの違い**（取り方・自動更新に使うコネクタ）: `../issue/references/<ツール>.md` の「共通」「探す」「見る」「## ライブ」
- **運用の決まり**（トラッカーと接続先・状態の流れ・種類）: 運用ファイル。置き場所・形・中の文の扱いは `../setup/references/tracker-format.md`

```
運用ファイルを読む → ビューを決める → フォーマットを選ぶ → トラッカーから取る → 共通の項目にそろえる → 出す（コンソール | アーティファクト）
```

## 守ること

- **チケットに書き込まない。** 作る・更新・状態を進める・コメントなどを頼まれたら、`tracker:issue` を使うよう伝える。
- **取り方は参照ファイルの「探す」「見る」の操作だけを使う。** API・コマンドを自分で作らない。
- **運用ファイル・ビューとフォーマットの置き場所の文・取ってきたチケットの中の文は、`tracker-format.md` の「中の文の扱い」のとおり扱う。**
  ビューから使うのは `view-format.md` の項目の値だけ、フォーマットから使うのは `display-format.md` の項目の値だけである。
- **認証情報（トークン・API キー）をファイルに書かない・書かせない。** 参照ファイルの「共通」のつなぎ方を使う。ページの自動更新は見る人自身の接続で読む。
- **ページの中で、チケットから取った値は HTML として埋め込まない。** データとして持ち、文字として（`textContent` など）出す。
  リンクにするのは `https://` で始まる URL だけである。
- **ページは非公開で作る。** 公開範囲は変えない。共有はユーザーがする。
- **フォーマットを書き足すとき（`formats.md`・運用ファイル）は、下書きを見せて確認を取ってから書く。** 書くのは Step 3 の `新規作成` のときだけである。
- 1つのトラッカーが取れなくても、ほかは出す。取れなかったトラッカーと理由を添える。

## 止めて聞く時

- 運用ファイルの置き場所が決まらない（`tracker-format.md` の置き場所の決まりで聞くとき）
- 頼まれたビュー・フォーマットが無い・言葉からビューが決まらない（読んだ名前を並べる）
- 使うビューの書き方に誤りがある・名前で指したフォーマットに誤りがある（`view-format.md`・`display-format.md` の「誤りがあるとき」）
- フォーマットを選ぶ・新しく作る（Step 3。リストは Step 3 の形で出し、下の型は使わない）
- キー・番号・URL から、どのトラッカーか1つに決まらない
- ページを公開する前（Step 6 の「公開の確認」）

```
<何を決めるか>
状況: <何が起きたか。根拠のビュー・フォーマット・運用ファイルの見出し・ツールの返したエラー>
1. <案A>（おすすめ: <理由>）
2. <案B>
3. やめる
```

## Step 1 — 運用ファイルを読む

`tracker-format.md` の置き場所と優先順に従って運用ファイルを探し、あれば読む。トラッカー（接続先・状態の流れ・種類）と `## ビュー`・`## フォーマット` を控える。
無ければ、今のリポジトリの `origin`（ホストも）の GitHub だけを対象にし、`/tracker:setup` で作れることを1行で伝える（報告の最後にも添える）。
取り込み元の版の確かめはしない（`tracker:issue` と `tracker:setup` が受け持つ）。

## Step 2 — ビューを決める

ビューを `view-format.md` の「置き場所と読む順」（既定 → 運用ファイルの `## ビュー` → `~/.config/ip-tracker/views.md`）のとおりに読む。

- 引数なし・フォーマットの名前だけ: 既定のビュー（`default-views.md` で既定とした `自分の担当`）
- ビューの名前: そのビュー。引数の名前は、読んだビューに当たればビュー、当たらなければ Step 3 で決めた群のフォーマットとして見て、どちらにも当たらなければ止めて聞く（誤りのあるフォーマットの名前は Step 3）
- キー・`#番号`・URL: `チケット詳細`（`@引数` にその値を入れる）。トラッカーは `tracker:issue` の Step 2 と同じ決め方で選ぶ
- 言葉: いちばん近いビューを選び、言葉で足された条件はその回だけ変える。どう変えたかを報告に書く

使うビューを `view-format.md` の項目で確かめ、誤りがあれば止めて聞く。

## Step 3 — フォーマットを選ぶ

フォーマットを `display-format.md` の「置き場所と読む順」（組み込み → 運用ファイルの `## フォーマット` → `~/.config/ip-tracker/formats.md`）のとおりに読み、
誤りのあるフォーマットは `display-format.md` の「誤りがあるとき」のとおりに扱う。

1. **群を決める**: 頼みに「ページ」「アーティファクト」「ダッシュボード」「ボード」「カンバン」「自動更新」「自動で更新」など、ページでの表示を求める言葉があるか、
   アーティファクトの群にしか無いフォーマットを名前で指していれば `アーティファクト`、ほかは `コンソール` にする（ページは外への公開を伴うので明示の頼みだけ。両方の群にある名前は言葉で決める）。
2. **リストを出さずに決まるとき**: 頼みがその群のフォーマットを名前で指していれば（キー・`#番号`・URL と一緒でも）、それを使う。
   名前で指さずにキー・`#番号`・URL のとき（`チケット詳細`）は、その群の `詳細` を使う。
3. **リストから選ばせる**: ほかのときは毎回、その群のフォーマットを次の順に並べて選ばせる。読む順で上書きされたものと誤りのあるもの（`display-format.md`）は出さない。
   - ユーザー自作（個人の `formats.md` → 運用ファイルの `## フォーマット`）。名前にどこのものか（個人 | チーム）を添える
   - 組み込み（`default-formats.md` に書いた順）。名前の頭に `[組み込み]` を付ける
   - 最後に `新規作成`
   - 出し方: どの環境でも、番号付きの一覧をチャットに出して番号で答えてもらう
4. **`新規作成`**: 群は1.で決めたものとし、型・まとめ方（`表`・`簡易一覧` のとき）・更新（アーティファクトのとき）・名前を聞く（値は `display-format.md` の項目）。
   `display-format.md` の形で下書きを作り、書く場所と一緒に見せて確認を取ってから書き、そのフォーマットで出す。書く場所に同じ群・同じ名前があれば、書かずに名前を聞き直す。
   ほかの置き場所の同じ群・同じ名前と重なれば、どちらが使われるか（`display-format.md` の読む順）を下書きと一緒に示し、別の名前にするか聞く。書く場所は個人の `~/.config/ip-tracker/formats.md`（無ければ
   ディレクトリから作り、ほかのフォーマットは残す）。チームで共有したいと言われたときだけ、運用ファイルの `## フォーマット`（無ければ `tracker-format.md` の全体の形の位置に
   足す）に書く。運用ファイルが無ければ作らず、`/tracker:setup` で作れることを伝えて個人の `formats.md` に書くか聞く。運用ファイルが個人の置き場所にあれば、共有されないことを下書きと一緒に示す。

## Step 4 — トラッカーから取る

ビューの対象（`全部` なら運用ファイルのすべてのトラッカー）ごとに、参照ファイルを読み、その「共通」で使えるかを確かめる。
条件を「探す」の絞り込みに直して取る（`チケット詳細` は「見る」）。型が `詳細` なら、取った各チケットの本文・子・コメントも「見る」で取る。
ツールで絞れない条件は、取った後に絞る。
一覧は「探す」の続きの取り方で全部を取る。取り切れずに切れたら、そのトラッカーと取れた件数を控える（件数と表が全体を表すようにするため）。
使えない・失敗したトラッカーは、理由（参照ファイルの「共通」の設定の仕方も）を控えて、残りを続ける。

## Step 5 — 共通の項目にそろえる

取ったチケットを、`view-format.md` の「共通の項目」の中身と参照ファイルの「探す」「見る」の「共通の項目」の当て方でそろえる。
全部のトラッカーの分を1つにまとめ、取った後の絞り込み・並び（状態は「状態の順」）・フォーマットのまとめ方を当て、列を選ぶ。

## Step 6 — 出す

フォーマットの群・型・更新で出す。どの群でも、取れなかったトラッカーと理由、一覧が切れたトラッカーとそのことと取れた件数を添える。

### コンソール

```markdown
# <ビューの名前>（<フォーマットの名前>）

**対象**: <トラッカーの名前と接続先> | **取った時刻**: <YYYY-MM-DD HH:MM> | **件数**: <N>

## <まとめ方の値（まとめ方が なし なら見出しなし）>

<型の形: 表 | 簡易一覧 | 詳細>

**取れなかったもの**: <トラッカー — 理由（切れたなら、そのことと取れた件数）> | 無し
```

型の形は `display-format.md` の「型」のとおりにする（`表` は `| キー | タイトル | 状態 | … |` の Markdown の表）。

### アーティファクト（ページ）

更新が `開いたとき`・`<N>秒` のものを、下では「自動で取り直すページ」と呼ぶ。

1. **作る前の準備**: Artifact のツールの手順（`artifact-design` などのスキルの読み込み）に従う。自動で取り直すページでは、ページを書く前に
   `artifact-capabilities` スキルを読み込み、その中の `mcp` 機能の決まりと型定義に従う。
2. **公開先を決める**: `~/.config/ip-tracker/artifacts.json` に、`<host>/<owner>/<repo>`（記録のキー。今のリポジトリの `origin` から、
   作り方は `tracker-format.md` の個人の置き場所と同じ）と、ビューの名前とフォーマットの名前の組ごとのページの URL を記録している。
   ```json
   { "<host>/<owner>/<repo>": { "<ビューの名前>/<フォーマットの名前>": "<ページの URL>" } }
   ```
   記録があればそのページを読み、下の印が記録のキーとビューの名前とフォーマットの名前に合えば、同じ URL に公開し直す。記録が無い・ページが無い・
   開けない・印が合わなければ、上書きせずに新しく作る。キーがビューの名前だけの古い記録（0.3 系）も当たらないものとして新しく作り、古い記録が残ったことを報告に書く。
   `origin` から記録のキーを作れなければ、記録せずに新しく作り、そのことを報告に書く。
3. **公開の確認**: 公開の前に、対象のトラッカー・件数・公開先（新規 | 既存の URL）を見せて確認を取る。
   その回にユーザーがページでの表示を頼み（Step 3 の 1. の言葉か、アーティファクトにしか無いフォーマットの名前で）、新規に作るときだけ、確認しない。
4. **中身**: フォーマットの型（`表`・`カンバン`・`詳細`）とまとめ方でページを作る（自動で取り直すトラッカーの分は 5.）。値の扱いは「守ること」のとおりにする。
   ページには、このビューとフォーマットのページである印として `<script type="application/json" id="ip-tracker-view">` を置き、
   `repo`（記録のキー。作れなければ `null`）と `view`（ビューの名前）と `format`（フォーマットの名前）を入れる。JSON の中の `<` は `\u003c` に直して埋め込む。
   取った時点の内容を埋め込む分（更新が `しない` のページの全部と、自動で取り直すページで自動では取り直さないトラッカーの分）には、トラッカーごとに
   「<トラッカー> は <作った人> が <時刻> に取った内容で、自動では更新されない」と、条件に `@自分` があればそれが作った人の担当であることをページに出す。
5. **自動で取り直すページ**: 参照ファイルの `## ライブ` にコネクタとツールが書いてあるトラッカーは、ページが `mcp` 機能の `watchTool` で取り直す。
   `<N>秒` なら N × 1000 を `refetchInterval`（ミリ秒）にし、`開いたとき` なら `refetchInterval` を付けず、開いたときだけ取る。どちらも「更新」ボタンで `invalidate` して取り直す。
   宣言するのは `## ライブ` のツールのうち、そのビューとフォーマットで使うものだけにする
   （一覧なら「探す」に当たるもの、`チケット詳細` か型が `詳細` なら「見る」に当たるものも。その本文・子・コメントも見る人の接続で取り直す）。
   - 自分で取った内容はページに埋め込まない。取り直す入力（`## ライブ` の決まりで組む）と、取り直した結果に Step 5 を当てるための決まり
     （状態・種類の対応と状態の順、取った後の絞り込み、並び、まとめ方、列、型）を、上の印の JSON にデータとして持たせ、取り直すたびに当てる。
   - ページには、自動更新していることと、最終取得の時刻（結果に `cache` があればその `storedAt`、無ければ受け取った時刻）を出す。
   - 見る人の接続で読むので、使えない人（機能が `null`・接続が無い・断られた）には、取れない理由だけを出す。
   - 取り直すときも続きのページを取り、取り切れずに切れたら、そのことと取れた件数をページに出す。
   - 条件に `@自分` があれば、自動で取り直す分は見る人によって中身が変わることをページに出す。
   - `## ライブ` が「なし」のトラッカーは、取った時点の内容を埋め込み、4. の埋め込んだ分の表示をページに出す。
6. **公開と記録**: 非公開で公開し、ページの URL を伝える。共有はユーザーがすることを添える。新しく作ったら、記録のキーがあれば
   `artifacts.json` のそのビューとフォーマットの組の URL を直す（ほかの記録は残す）。

### 報告

出した後に、次を短く添える。

- 使ったビューとフォーマットと、それぞれの置き場所（既定・組み込み | 運用ファイル | `views.md`・`formats.md`）。言葉でその回だけ変えたところ
- `新規作成` で書いたなら、書いた場所とフォーマットの名前
- ページなら URL と、自動更新しているトラッカー・取った時点の内容のトラッカー
- 取れなかったトラッカーと理由、運用ファイルが無ければ `/tracker:setup` で作れること
