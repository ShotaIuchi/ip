# 取り込み元（外の文書）の読み方

運用の決まりは、リポジトリの外の人向けの文書に書かれていることがある。その文書を正しい情報源のままにして、運用ファイルに写す。
ここには、取り込み元の共通の決まりと写し方・取り込み直し（`setup` と `issue` で共通）と、種類ごとの違いを書く。
記録の形と、取り込んだ文書の中の文の扱いは `tracker-format.md` にある。

## 共通

- **読み取りだけ**: 取り込み元へは読み取りだけを行い、書き込まない。
- **場所の確かめ**: 場所は使う前に毎回（`setup` で受け付けるときも、運用ファイルから読み戻したときも）その種類の「場所の書き方」に合うかを確かめ、
  合わなければ届かないとして扱う（運用ファイルは PR で書き換えられる）。コマンドや `gh api` のパスに差し込む部品（Docs・Gist の id、ホスト・owner・
  repo・ブランチ・GitHub のパス）に `..`・`?`・`#`・`%` を含むものは使わない（URL の種類は、その「場所の書き方」でだけ確かめる）。
  `gh` は場所のホストへ保存されたログインを送るので、ホストが `github.com` か今のリポジトリの `origin` のホストでなければ、取りにいく前にホストを見せて聞く。
  `gh api` には、`github.com` でも `--hostname '<host>'` を常に付ける（下のコマンドでは略す。`GH_HOST` に左右されないため）。
- **値の渡し方**: 場所・ID・パスはシェルに単一引用符で囲んで渡す（中の `'` は `'\''`）。
- **認証情報を付けない・書かない**: Cookie・トークン・`Authorization` をコマンドに付けない・運用ファイルにも場所にも書かない。
  つなぎ方は、各種類の「読み方」にあるログイン済みのコネクタ・`gh` だけを使う。
- **版の印**: `<印の種類>:<値>`（`modified:` / `version:` / `commit:` / `etag:` / `sha256:`）で記録する。印の種類は取り込むときに種類ごとの「版の印」で決め、
  確かめでは記録と同じ種類の印を取って、文字列が同じかどうかだけを比べる（大小は比べない）。取り込むときは印を2回取って比べ、
  値が揺れるなら取り込み元にせず、そのことを伝えて聞く。
  その種類の印が取れなければ届かないとして扱い、`setup` で取り込み直して印の種類を決め直すよう伝える。
- **本文の sha256**: 本文を一時ファイル（`mktemp`）に書き、HTML なら `perl -0777 -pe 's/<(script|style)\b.*?<\/\1>//gis; s/<[^>]*>//g; s/\s+/ /g'`
  で文字だけにしてから `shasum -a 256` に通す。確かめのたびに、ハッシュのためだけに本文を取ってよい（解釈はしない）。
- **印と本文の順**: 取り込むときは、先に版の印を取り、それから本文を読む（途中で直されても、次の確かめで気づける）。
- **届かないこと**: 権限が無い・通信できない・コネクタや `gh` が無い・場所に文書が無いこと。見分け方は種類ごとの「届かないとき」。
  届かないときにどうするかは、呼んだスキル（`setup` / `issue`）の SKILL.md に従う。

## 写し方と取り込み直し

- 文書の全文を読み、運用の決まりを `tracker-format.md` の決まった見出し（どのトラッカーのどの `###` か）に振り分けて写す。
  言い回しはできるだけ保ち、決まりを足したり言い換えて意味を変えたりしない。どの見出しにも入らない文は写さず、写さなかったことを伝える。
- 写した見出しが、その取り込み元の「受け持った見出し」になる。1つの見出しは1つの取り込み元だけが受け持ち、その取り込み元からだけ作る。
  取り込むとき、別の取り込み元が受け持つ見出しや、ツールから集めた値と食い違う決まりは、下書きで示して聞く。
  その取り込み元が `--from` でも言葉でも示されていない `setup` では受け持たれた見出しを書き換えず、ツールから集めた値と食い違えば、
  下書きに注として示し、元の文書を直すよう勧める。
- **取り込み直し**も全文を振り分け、その取り込み元が受け持った見出しだけを作り直す。ほかの見出し（ツールから集めた・答えた・別の取り込み元の）は残す。
  ただし、どの取り込み元も受け持っていない見出しに入る決まりは差分に「新しく受け持つ」と出し（ツールの値や答えと食い違えば上のとおり聞く）、
  決まりが消えた受け持ちの見出しは「なし」にして受け持ちから外すことを差分に出す。
  受け持った見出しが手で直されていても、元の文書を正しい情報源として作り直し、上書きになるところを差分に出す。
- 写す中身が前と同じなら、`## 取り込み元` の版の印と取り込んだ日だけを更新する。これも書き込みなので、1行で確認を取る。
- 書いたら、`## 取り込み元` の表のその行（種類・場所・版の印・受け持った見出し・取り込んだ日）を足すか更新する。

## Google Docs

- **場所の書き方**: 文書の URL `https://docs.google.com/document/d/<id>`（後ろの `/edit` などは落とす）。読むときは `<id>` を `fileId` に使う。
- **読み方**: Google Drive のコネクタ。本文は `read_file_content`（`fileId`）で取る。読みにくい形で返れば `download_file_content`（テキストで書き出す）で取る。
- **版の印**: `modified:<値>`。値は `get_file_metadata`（`fileId`、`excludeContentSnippets: true`）の `modifiedTime`。
- **届かないとき**: Google Drive のコネクタ（`get_file_metadata` など）がその環境に無い、または権限が無い・見つからないエラーが返る。

## Gist

- **場所の書き方**: Gist の URL `https://gist.github.com/<owner>/<id>`（ホストは `github.com`）か、GitHub Enterprise の `https://<host>/gist/<owner>/<id>`。読むときは `<id>` を使う。
- **置き場所**: `gh api 'gists/<id>' --jq '.public'` が `false`（秘密の Gist）なら、URL を知っていれば誰でも読めるので、場所をリポジトリの
  `TRACKER.md` に書かない。書く前に止め、個人の置き場所（`tracker-format.md`）に書くよう勧める。
- **読み方**: `gh api 'gists/<id>'`。本文は `files` の各ファイルの `content`。
- **版の印**: `version:<値>`。値は `gh api 'gists/<id>' --jq '.history[0].version'`
- **届かないとき**: `gh` が無い・そのホストにログインしていない（`gh auth status --hostname '<host>'` で見分ける）、`Not Found`（404）が返る、通信のエラー。

## GitHub のファイル

README など、GitHub のリポジトリにあるファイル（github.com と GitHub Enterprise。非公開のリポジトリも同じ）。

- **場所の書き方**: `<host>/<owner>/<repo>/<パス>（ブランチ: <ブランチ>）`。ファイルの URL（`.../blob/<ブランチ>/<パス>`）で示されたら、URL エンコードを戻してこの形に直す。
  ブランチの指定が無ければ、そのリポジトリの既定のブランチ（`gh api 'repos/<owner>/<repo>' --jq '.default_branch'`）を書いておく。
- **読み方**: `gh api -X GET -H 'Accept: application/vnd.github.raw+json' 'repos/<owner>/<repo>/contents/<パス>' -f ref='<ブランチ>'`
  （`<パス>` は contents の URL の中でだけ `/` を残して各部分を URL エンコードし、`-f` の値は生のまま渡す（`gh` がエンコードする）。版の印のコマンドも同じ）。
- **版の印**: `commit:<値>`。値はそのパスとブランチの最新のコミットの sha。
  `gh api -X GET 'repos/<owner>/<repo>/commits' -f path='<パス>' -f sha='<ブランチ>' -f per_page=1 --jq '.[0].sha'`
- **届かないとき**: `gh` が無い・そのホストにログインしていない、`Not Found`（404）が返る、印が空（`null`。そのブランチにそのパスが無い）、通信のエラー。

## Confluence

- **場所の書き方**: ページの URL `https://<site>.atlassian.net/wiki/spaces/<スペース>/pages/<id>`（後ろのタイトルは落とす）。
- **読み方**: Atlassian MCP の `getConfluenceContent`（`cloudId` にサイト、`content_url` にページの URL、`detail: "full"`、
  `content_format: "markdown"`）。サイトの決め方は `../../issue/references/jira.md` の「共通」と同じ。
- **版の印**: `version:<値>`。値は `getConfluenceContent` が返す版の `number`。取り込むときに読めなければ `sha256:`（「共通」の本文の sha256）。
- **届かないとき**: Atlassian MCP がその環境に無い・認証が切れている、または権限が無い・見つからないエラーが返る。

## URL

上のどれにも当たらない、ログインなしで読める公開のページ。

- **場所の書き方**: `https://` で始まる URL だけを受け付ける。ほかのスキームと、`https://<user>:<pass>@<host>/` のようにユーザー情報を含む URL は受け付けない。
  クエリやパスに認証情報（トークン・署名・鍵）を含む URL も受け付けない。受け付けない URL は場所として書かない（そのことを伝える）。
- **読み方**: 応答のヘッダと本文を一時ファイルに分けて取る（`-q` で `~/.curlrc` を読まず、転送は `https` の先だけを追い、待ちは `--max-time`、大きさは `--max-filesize` で切る）。
  HTML で返れば、本文の文だけを読む。
  `curl -q -sS -L --fail --max-time 30 --max-filesize 5M --proto '=https' --proto-redir '=https' -D '<ヘッダ>' -o '<本文>' -w '%{url_effective}' '<URL>'`
- **版の印**: 上の取り方の最後の応答のヘッダに `ETag` があれば `etag:<値>`（`W/` が付いていればそのまま）、無ければ `sha256:`（「共通」の本文の sha256。
  `Content-Type` が `text/html` なら HTML として扱う）。`HEAD` は断るサーバーがあるので使わない。
- **届かないとき**: `curl` が 0 以外で終わる（通信のエラー・時間切れ・大きすぎる・4xx・5xx・`https` 以外への転送）、または最後の URL（`-w` の出力）や中身が
  ログイン・認証の画面である。
