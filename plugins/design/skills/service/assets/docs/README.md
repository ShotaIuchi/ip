## 文書の一覧

| 文書 | ファイル | 書くこと | 読むとき |
|---|---|---|---|
| 用語集 | [glossary.md](glossary.md) | 言葉の意味。ほかの文書はすべてこの定義に従う | 最初に。言葉の意味に迷ったとき |
| 構想 | [concept.md](concept.md) | 何を、誰に、なぜ提供するか。収益、リスク、Phase の順番と最初に検証すること | サービスの狙いを知りたいとき |
| 要求仕様 | [requirements.md](requirements.md) | サービスが何をするか（機能と決まり）。守るべき法令、非機能要件、判定に使う数値 | 機能の振る舞いを知りたいとき |
| 基本設計 | [design.md](design.md) | どう作るか（技術構成、データモデル、機能ごとの仕組み） | 実装するとき |
| ロードマップ | [roadmap.md](roadmap.md) | Phase ごとに出す機能の一覧（機能の名前と、その Phase でどこまで出すか） | 今の Phase で何を作るかを確かめたいとき |
| 判断記録 | [decisions/](decisions/README.md) | ほかの案と比べて決めたこと（1件1ファイル）と、まだ決めていないことの一覧 | なぜそう決めたか、何が決まっているかを確かめたいとき |
| 機能の仕様 | specs/ | 1つの機能を実装するための仕様（`dev:spec` で作る。最初の仕様書ができたら、この行をリンク `[specs/](specs/)` にする） | その機能を実装するとき |

読む順番: 用語集 → 構想 → 要求仕様 → 基本設計。ロードマップと判断記録は、必要なときに引く。実装するときは、作る機能が今の Phase に入っているかをロードマップで確かめる。
