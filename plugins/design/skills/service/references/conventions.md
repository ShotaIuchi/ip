# 書き方の決まり（正本）

このファイルが「書き方の決まり」の正本である。リポジトリの `docs/README.md` には、下の「決まりの本文」をそのまま写す。
写すときは、次の2行の目印で挟む（`<版>` はこのファイルの版）:

```
<!-- design:conventions v<版> begin -->
<!-- design:conventions end -->
```

版: 1

目印の間は、このファイルと同じ内容に保つ。比べるときは、行末の空白と空行の違いは無視して、中身で比べる（版が同じでも中身が手で変えられていることがある）。
目印の間は決まりの本文の写しなので、`< >` や「→ §」の例が入っている。文書の整合を確かめるときは、目印の間を対象から外す。リポジトリだけの決まりは、目印の外の「このリポジトリだけの決まり」に書く。

---

## 決まりの本文

- 言葉は glossary.md の定義どおりに使う。定義にない言い換えをしない。新しい言葉を使うときは、先に glossary.md に足す
- 1つの決まりは、詳しくは1か所にだけ書き、ほかの場所からはリンクする。同じ説明を複数の場所に書くと、片方だけ直したときに食い違うため
- 文書ごとに書くことを分ける。構想には「なぜ・誰に」、要求仕様には「何をするか」、基本設計には「どう作るか」、ロードマップには「いつ出すか（Phase ごとの機能の名前と、その Phase でどこまで出すか）」だけを書く
- 参照は、同じ文書の中なら「→ §2.1」、ほかの文書なら「→ requirements.md §2.1」、判断記録なら「→ decisions/0003-xxx.md」と書く。文書の名前は docs/ からの相対パスで書く（docs/decisions/ の中から書くときも同じ）。docs/ の外（AGENTS.md、.claude/rules/）から書くときだけ「→ docs/design.md §7」と docs/ を付ける。用語集の「詳しく」の列では矢印を付けない
- 節の番号は、一度付けたら変えない。参照が切れるため。新しい節は末尾の番号で足すか、関係する節の下位の節（§2.3 など）にする。使わなくなった節は消さずに「（廃止 → <移した先>）」と書いて番号を残す。まだ書けない節は「未定」と書く
- ほかの案と比べて選んだことは、判断記録（`docs/decisions/NNNN-<名前>.md`、1件1ファイル）に書く。本文には決めたことだけを書き、理由は判断記録へリンクする
- 判断記録にするのは、ほかの案と比べて選んだことのうち、後から変えると手戻りが大きいもの（技術、構成の分け方、データの置き場所、外部サービスなど）。案が1つしか無いものや、すぐに変えられるものは本文に書けば足りる
- 判断記録の状態は proposed（検討中）/ accepted（決定）/ rejected（見送り）/ deprecated（廃止）/ superseded by NNNN（置き換え）のどれか。決めた判断を変えるときは、元の記録を書き換えず、新しい記録を作って元の記録を superseded にし、本文の古くなった記述も新しい判断に合わせて直す
- まだ決めていない設計の判断は、状態を proposed にした判断記録にする。判断記録にしない未決（事業の数字、外部への問い合わせなど）は、decisions/README.md の「その他の未決」に書く
- 判定や制限に使う数値（しきい値、期限、上限など）は、実装の前に要求仕様にまとめて決めておく。決めずに実装すると、実装する人（AI を含む）がその場で決めてしまうため
- 図は Mermaid で書く。全体の図（システムと外の人・外のシステム）から、部品の図（アプリ、API、DB など）へと、段階的に詳しくする
- 文書を足す・消す・名前を変えるときは、docs/README.md の「文書の一覧」も直す。docs/README.md と glossary.md の名前を変えるときは、リポジトリ直下の AGENTS.md も直す（AGENTS.md がこの2つを名前で指しているため）
- 判断記録を足す・状態を変えるときは、decisions/README.md の一覧も直す
